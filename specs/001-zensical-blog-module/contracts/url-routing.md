## Locked Routes

| Page | URL Pattern | Source file (canonical) | Generated file (`docs/.bloggen/`) |
|------|-------------|------------------------|----------------------------------|
| Blog index | `/<blog_dir>/` | `docs/<blog_dir>/index.md` | `docs/.bloggen/<blog_dir>/lists/latest.md` |
| Post | `/<blog_dir>/<post_slug>/` | `docs/<blog_dir>/posts/<file>.md` (source; not a generated page) | — |
| Archive landing | `/<blog_dir>/archive/` | `docs/<blog_dir>/archive/index.md` | `docs/.bloggen/<blog_dir>/archive/index.generated.md` |
| Year page | `/<blog_dir>/archive/<year>/` | `docs/<blog_dir>/archive/<year>.md` | `docs/.bloggen/<blog_dir>/archive/<year>.generated.md` |
| Tags landing | `/<blog_dir>/tag/` | `docs/<blog_dir>/tag/index.md` | `docs/.bloggen/<blog_dir>/tag/index.generated.md` |
| Per-tag page | `/<blog_dir>/tag/<tag_slug>/` | `docs/<blog_dir>/tag/<tag_slug>.md` | `docs/.bloggen/<blog_dir>/tag/<tag_slug>.generated.md` |
| Categories landing | `/<blog_dir>/category/` | `docs/<blog_dir>/category/index.md` | `docs/.bloggen/<blog_dir>/category/index.generated.md` |
| Per-category page | `/<blog_dir>/category/<category_slug>/` | `docs/<blog_dir>/category/<category_slug>.md` | `docs/.bloggen/<blog_dir>/category/<category_slug>.generated.md` |

## Canonical File Rules

1. **Canonical files** (left column above) are the URL-bearing files. They
   are either user-authored overrides or generated by the emitter.
2. **Generated files** (`docs/.bloggen/…`) are implementation artifacts.
   They produce listing content that is either (a) included by the canonical
   file or (b) appended to it via the sentinel protocol.
3. If a canonical file already exists (user-authored), its content is
   preserved; the generated listing is appended using the sentinel protocol
   (see `data-model.md` §10).
4. If a canonical file does not exist, the emitter creates it with only the
   generated listing content (no custom preamble).

## Post Slug Derivation

Priority order:

1. `slug` field in front matter — used verbatim (after validation).
2. Source filename stem, with leading date prefix stripped.
   - Pattern: `YYYY-MM-DD-<name>.md` → `<name>`
   - Pattern: `<name>.md` → `<name>`
3. Slug is then validated: must match `[a-z0-9][a-z0-9-]*` after applying the
   slugification algorithm (R-05). If not, emit a warning and apply the
   algorithm to the filename stem.

**Post slug collision**: if two posts produce the same slug, append `-2`,
`-3`, etc. (same collision policy as taxonomy terms) and emit a warning.

---

## Taxonomy Slug Derivation

Uses the deterministic algorithm from `research.md` R-05 and
`references/page_map_naming_conventions.md` §3.2–§3.4:

```
label → NFKD normalize → strip combining marks → casefold
      → replace non-[a-z0-9]+ with "-" → collapse "-"
      → strip leading/trailing "-" → truncate to 80 chars → rstrip("-")
      → if empty → "x"
```

Collision resolution: sort colliding labels by Unicode code-point order;
assign base slug to first, `<base>-2` to second, etc. Emit a warning listing
all collisions and their assigned slugs.

Explicit override: `BlogConfig.tag_slug_map` / `category_slug_map` entries
take absolute priority over the algorithm.

## Nav Contract

| Condition | Module behaviour |
|-----------|-----------------|
| Nav defined, contains `<nav_label>: <nav_path>` | No-op. |
| Nav defined, does NOT contain Blog entry | Emit `WARNING` with suggested nav entry. Do not modify nav. |
| Nav not defined | Synthesise minimal nav with `<nav_label>: <nav_path>` as top-level entry. |
| `--apply-nav` flag present | Patch `mkdocs.yml` nav to add `<nav_label>: <nav_path>` as first top-level entry. All other nav entries are unchanged. |

`<nav_label>` and `<nav_path>` default to `"Blog"` and `"blog/index.md"`
respectively; configurable via `BlogConfig.nav_label` / `BlogConfig.nav_path`.
